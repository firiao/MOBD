# Лабораторная работа №2. Базовые SQL-запросы и фильтрация данных

## Цель работы

Наполнить спроектированную в лабораторной работе №1 базу данных маркетплейса согласованными тестовыми данными и составить набор запросов на выборку и фильтрацию: `DISTINCT`, `WHERE` с `AND`/`OR`, предикаты `BETWEEN`, `IN`, `ILIKE`, `IS NULL`, сортировка по нескольким столбцам и постраничный вывод.

## 1. Исходная схема

Используется схема из лабораторной работы №1 ([`../lab1/schema.sql`](../lab1/schema.sql)) — 13 таблиц:

`users`, `sellers`, `addresses`, `categories`, `products`, `stock`, `carts`, `cart_items`, `orders`, `order_items`, `payments`, `reviews`, `deliveries`.

Связи: «один-ко-многим» (продавец → товары, покупатель → заказы), «многие-ко-многим» через `order_items` и `cart_items`, иерархия категорий через самоссылку `categories.parent_id`, «один-к-одному» (`stock`, `payments`, `deliveries`).

## 2. Наполнение базы данных

Скрипт наполнения — [`seed.sql`](seed.sql). Он оформлен в одной транзакции, начинается с `TRUNCATE ... RESTART IDENTITY CASCADE`, поэтому может выполняться повторно и всегда даёт одинаковый набор строк. Для воспроизводимости случайных значений задано зерно: `SELECT setseed(0.42)`.

| Таблица | Строк | Как сформирована |
|---|---:|---|
| `users` | 119 | 108 покупателей, 10 продавцов, 1 администратор |
| `sellers` | 10 | по одному магазину на пользователя-продавца |
| `addresses` | 118 | по одному адресу покупателя + второй у каждого 10-го |
| `categories` | 20 | 5 корневых и 15 дочерних категорий (глубина 2) |
| `products` | 1000 | `generate_series`, случайные цена, категория, продавец |
| `stock` | 1000 | одна складская строка на каждый товар |
| `carts` | 50 | корзины первых 50 покупателей |
| `cart_items` | 150 | по 3 позиции в каждой корзине |
| `orders` | 1000 | заказы за последние 180 дней |
| `order_items` | 3000 | по 3 позиции в каждом заказе |
| `payments` | 800 | по заказам в статусах `paid`, `shipped`, `delivered`, `cancelled` |
| `reviews` | 500 | по одному отзыву на разные товары |
| `deliveries` | 700 | по оплаченным, отправленным и доставленным заказам |

Согласованность данных:

- адрес в заказе выбирается только из адресов этого же покупателя;
- `order_items.unit_price` фиксирует цену товара на момент заказа, поэтому последующее изменение цены в `products` не искажает историю;
- пара `(order_id, product_id)` в `order_items` уникальна;
- отзывы не нарушают ограничение `UNIQUE (user_id, product_id)`;
- часть данных намеренно содержит `NULL`: у 200 товаров нет описания, у 27 покупателей не указан телефон, у части платежей не заполнено `paid_at`. Это нужно для демонстрации `IS NULL` и трёхзначной логики.

Запуск:

```bash
createdb marketplace
psql -d marketplace -f ../lab1/schema.sql
psql -d marketplace -f seed.sql
psql -d marketplace -f queries.sql
```

## 3. Запросы

Все запросы находятся в файле [`queries.sql`](queries.sql). Полный вывод, полученный при выполнении скрипта, сохранён в [`results.txt`](results.txt).

### Запрос 1. `DISTINCT` и псевдонимы столбцов

**Назначение:** получить уникальные пары «категория — продавец», то есть показать, какие магазины представлены в каких категориях, без повторяющихся сочетаний.

```sql
SELECT DISTINCT
       p.category_id AS category,
       c.name        AS category_name,
       p.seller_id   AS seller,
       s.store_name  AS store
FROM products AS p
JOIN categories AS c ON c.id = p.category_id
JOIN sellers    AS s ON s.id = p.seller_id
WHERE p.is_active
ORDER BY category_name, seller
LIMIT 15;
```

Фрагмент результата:

```text

----------+---------------+--------+------------
       18 | Велосипеды    |      3 | Магазин 3
       18 | Велосипеды    |      8 | Магазин 8
       17 | Детективы     |      2 | Магазин 2
       17 | Детективы     |      7 | Магазин 7
       10 | Джинсы        |      5 | Магазин 5
       10 | Джинсы        |     10 | Магазин 10
       11 | Кроссовки     |      1 | Магазин 1
       11 | Кроссовки     |      6 | Магазин 6
        9 | Куртки        |      4 | Магазин 4
        9 | Куртки        |      9 | Магазин 9
       13 | Мебель        |      3 | Магазин 3
```

Без `DISTINCT` каждая пара повторялась бы столько раз, сколько товаров у данного продавца в данной категории.

### Запрос 2. Фильтрация по нескольким условиям с `AND` и `OR`

**Назначение:** отобрать активные товары, которые либо дешевле 1000 ₽, либо дороже 45 000 ₽, при этом относятся к категориям «Смартфоны»/«Ноутбуки» либо продаются магазином №1. Скобки задают приоритет: `AND` связывает сильнее, чем `OR`.

```sql
SELECT p.id, p.title, p.price, c.name AS category
FROM products AS p
JOIN categories AS c ON c.id = p.category_id
WHERE (p.price < 1000 OR p.price > 45000)
  AND p.is_active
  AND (c.name IN ('Смартфоны', 'Ноутбуки') OR p.seller_id = 1)
ORDER BY p.price DESC
LIMIT 10;
```

Фрагмент результата:

```text

-----+----------------+----------+-----------
  76 | Ноутбуки №76   | 49821.50 | Ноутбуки
 975 | Смартфоны №975 | 49798.82 | Смартфоны
  46 | Ноутбуки №46   | 49437.50 | Ноутбуки
 766 | Ноутбуки №766  | 48914.12 | Ноутбуки
  90 | Смартфоны №90  | 48897.04 | Смартфоны
 435 | Смартфоны №435 | 47957.89 | Смартфоны
 361 | Ноутбуки №361  | 47576.86 | Ноутбуки
  50 | Кроссовки №50  | 47377.43 | Кроссовки
 451 | Ноутбуки №451  | 46937.63 | Ноутбуки
 826 | Ноутбуки №826  | 46781.64 | Ноутбуки
(10 rows)
```

Товар «Кроссовки №50» попал в выборку по второму условию — он принадлежит магазину №1, хотя его категория не входит в список.

### Запрос 4. Предикат `ILIKE`

**Назначение:** найти все товары, в названии которых встречается «смартфон», без учёта регистра. `%` заменяет любую последовательность символов, `_` — ровно один символ.

```sql
SELECT id, title, price
FROM products
WHERE title ILIKE '%смартфон%'
ORDER BY price DESC
LIMIT 10;
```

### Запрос 5. `IS NULL` и `COALESCE`

**Назначение:** вывести товары без описания, подставив вместо `NULL` понятный текст.

```sql
SELECT id,
       title,
       COALESCE(description, 'Описание не указано') AS description
FROM products
WHERE description IS NULL
ORDER BY id
LIMIT 10;
```

Фрагмент результата:

```text
 id |     title     |     description
----+---------------+---------------------
  5 | Кроссовки №5  | Описание не указано
 10 | Учебники №10  | Описание не указано
 15 | Смартфоны №15 | Описание не указано
 20 | Кроссовки №20 | Описание не указано
 25 | Учебники №25  | Описание не указано
 30 | Смартфоны №30 | Описание не указано
 35 | Кроссовки №35 | Описание не указано
 40 | Учебники №40  | Описание не указано
 45 | Смартфоны №45 | Описание не указано
 50 | Кроссовки №50 | Описание не указано
(10 rows)
```

Проверка трёхзначной логики: сравнение с `NULL` через `=` не возвращает строк, потому что результатом является `UNKNOWN`, а не `TRUE`.

```sql
SELECT count(*) AS rows_with_eq_null
FROM products
WHERE description = NULL;
```

```text

-------------------
                 0
(1 row)
```

### Запрос 8. Статистика по `NULL`

**Назначение:** показать разницу между `count(*)` (считает все строки) и `count(description)` (не считает строки с `NULL`).

```sql
SELECT count(*)                      AS total_products,
       count(description)            AS with_description,
       count(*) - count(description) AS without_description
FROM products;
```

```text
 total_products | with_description | without_description
----------------+------------------+---------------------
           1000 |              800 |                 200
(1 row)
```
